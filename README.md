# dsh-a-plan-board · DSH 计划看板

> 一块和模型共同维护的任务看板：**任务写在文件里，执行交回模型**。
> 你在面板上挑任务、批注、否决；点一次「让他做」，模型按顺序开工，做完自己打勾。

这是一个 [DeepSeek Harness（DSH）](https://github.com/deepseek-ai) 插件（bundle），
包含 Host 半区、浏览器半区、一个模型侧工具组，以及一份随插件分发的执行约定技能。

## 它解决什么问题

和模型协作时，任务列表通常散落在对话里：说过的话会沉底，做完的没标记，改主意了也留不下痕迹。

这个插件把它变成一份**文件即真相**的计划板：

- 任务是 markdown 里的一行，带「做法」「验收」，可以批注、可以否决；
- 你在看板上挑选和排序，形成"接下来"队列；
- 点一次按钮，队列被交给模型，模型开工时自己标进行中、做完标完成；
- 一切状态变化都回写到文件，面板、会话视图、聊天卡片读的是同一份数据。

## 界面

三个入口，同一份数据：

| 入口 | 位置 | 用途 |
|---|---|---|
| 计划板页 | 左侧导航图标 → 整页 | 主界面：正在做、整体分组、接下来队列 |
| 计划板视图 | 会话头部的视图行 | 与当前会话绑定的同一块板 |
| `/aboard` 卡片 | 对话流 | 输入 `/aboard` 得到一张带进度的摘要卡，可一键跳回面板 |

面板顶部是压缩过的状态条（运行状态、完成数、进度条、搜索），下面是三段：

```
正在做 · 1                 ● 运行中          排队 2 条   ▾
◐ 给模型一个写板工具…        P0   3m12s   ✎ ✓
  验收：提交「打通 API」这类简短条目会被工具退回…
──────────────────────────────────────────────
排队中 · 2 条
#1  给模型一个更新条目状态的工具            P0   排队
#2  让 /aboard 命令既能给人看也能当接口      P0   排队
```

左列是**整体**（按阶段分组、可折叠、组头带子进度、完成的收进「已完成 n」），
右列是**接下来**（你的队列，可拖拽排序、可切串行/并行、可整队清空）。

支持：拖拽入队/排序/移出、优先级 P0–P3、批注、否决（灰掉保留）、搜索、
键盘操作（↑↓ 移动、空格选择、0–3 设优先级、Enter 标进行中）、
中英双语、亮暗主题（所有颜色都取自主题 token，并对配色做了 WCAG 对比度校准）。

## 安装

插件包就在仓库根目录（`package.json` 声明了 `dsh.bundle.patch` 与 `dsh.client`）。

**本地安装**：DSH → 设置 → Plugins → Add plugin → 选择本目录；
或者用插件管理器安装：

```text
plugin_manager install_bundle target=/Users/<you>/codespace/plan-board
```

安装后需要刷新页面；若 Host 端代码有更新，需要重启 DSH（Host 在发布时会快照插件包，
热更新依赖 `/plugins/events` 流，该流不可用时只能重启）。

## 计划文件格式

数据在**当前会话工作区**的 `.dsh/plan-board.md`。建议把它加进 `.gitignore`（属于本地数据）。

```md
# 计划板 · 项目名

> 目标：一句话说明这一轮要达成什么。

## P1 · 分组名

- [ ] 一句完整人话的任务标题  @P0 @选 @start=2026-11-15T16:53
  做法：具体怎么做。
  验收：怎么算做完，尽量写可验证的标准。
  批注：用户的意见，会写回文件。
```

**状态**：`[ ]` 未开始 · `[~]` 进行中 · `[x]` 完成 · `[-]` 已否决（灰掉保留）。

**标记**：`@P0`–`@P3` 优先级 · `@选` 已挑选 · `@弃` 已否决 · `@start=` 开始时间 · `@序=N` 拖拽顺序。

样例见 [`examples/plan-board.md`](examples/plan-board.md)。

## 命令

`/aboard` 既给人用，也是**面板和模型之间的接口**（Client 通过 `remote.commands.execute` 调用同一批子命令）。

| 子命令 | 作用 |
|---|---|
| `/aboard` | 结构化摘要（聊天卡片用） |
| `/aboard list` | 人读的分组摘要 |
| `/aboard json` | 完整结构化数据 |
| `/aboard pick <n>` | 选中 / 取消选中 |
| `/aboard prio <n> <P0-P3\|->` | 设优先级 |
| `/aboard doing\|done\|undone <n>` | 状态流转 |
| `/aboard drop\|undrop <n>` | 否决 / 恢复 |
| `/aboard note <n> <text>` | 追加批注 |
| `/aboard reorder <i,j,k>` | 写入队列顺序 |
| `/aboard next` | 按队列顺序开工第一条 |
| `/aboard start <n>` | 开工指定条目 |
| `/aboard batch <serial\|parallel> <i,j,k>` | 批量派活 |
| `/aboard clear` | 清空队列里的选择与优先级（不动任务） |
| `/aboard goal <text>` | 改本轮目标 |

## 模型侧工具

| 工具 | 作用 | 校验 |
|---|---|---|
| `plan_board_write` | 往指定分组写任务 | 标题 ≥ 20 字、必须有做法与验收，否则拒绝并给出补齐提示 |
| `plan_board_status` | 切换条目状态，进行中写 `@start`，完成清除 | 序号/状态必须合法 |

这两个工具让模型**自己维护看板**：写计划、开工、打勾，不需要人代劳。

## 技能

`skills/plan-board/SKILL.md` 随插件分发，通过 `dsh-skill-filesystem` 的
`bundledSkillDir` 挂载（见 `cordis.patch.yml`），因此**装到任何工作区都自带执行约定**。

它规定了：开工前必须用工具标进行中、做完标完成、卡住时留批注而不是假装完成、
不许改条目原文、不许清理别人的选择标记、最后只做简短汇总。

派活消息因此可以极短：

```
【计划板】串行做第 4、5、6 条。执行约定：加载 skill `plan-board`。
```

## 架构

```
                     ┌──────────────────────────────┐
  对话 / 模型  ──────▶│ Host 半区 (index.js)          │
                     │  /aboard 命令 · 两个工具      │
                     └──────────────┬───────────────┘
                                    │ 读写
                                    ▼
                        .dsh/plan-board.md  ← 唯一真相
                                    ▲
                     ┌──────────────┴───────────────┐
   面板 / 卡片  ─────▶│ Client 半区 (client.js)      │
                     │ 读: remote.workspaceFiles     │
                     │ 写: remote.commands.execute   │
                     └──────────────────────────────┘
```

- **Host 半区**：注册命令与工具，解析/改写 markdown，负责所有写入。
- **Client 半区**：注册四个插槽入口（左栏图标、整页面板、会话视图、聊天卡片行），
  读文件用只读的 workspace-files Remote（不产生会话记录），写文件复用命令通道。
- **为什么写要走命令**：DSH 的第三方 bundle 没有自定义 Remote 命名空间，
  但"命令"是官方支持的 UI → Host 调用入口；命令产生的事件在聊天里被
  `conversation.chat.commandview` 接管，机器调用渲染为空，不打扰对话。
- **唤醒机制**：开工时 Host 调 `agent.followup()` 投递一条真实的用户消息，模型因此被唤醒。

没有改任何模型提示词，没有往会话日志里写自定义事件类型。

## 开发

```bash
# 本地目录以 link 方式装进 profile，改文件即改源码
plugin_manager install_bundle target=/absolute/path/to/this/repo
```

改完代码后的生效方式：

- **客户端改动**：刷新页面（bundle 会重新发布）。
- **Host 改动**：禁用再启用插件（重启 Loader 条目），或重启 DSH。
- 一键切换：设置 → Plugins → 关闭再打开「计划板」。

`docs/DESIGN.md` 记录了完整的需求演进与设计取舍（含被推翻的方案）。

## 已知限制

- 面板 3 秒轮询文件，没有用文件系统监听；
- 「当前在跑哪个工具」未接入，只显示会话运行/空闲；
- 拖拽排序只在「接下来」列内生效，不能跨分组拖动条目；
- 并行模式依赖模型自己派子代理，插件只负责把批次交代清楚；
- 包名仍是 `@local/plan-board`，发布到 npm 前需要改成正式 scope。
