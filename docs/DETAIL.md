# Plan board / 计划板

> v0.2 — 看板工作台：能看清正在做什么、能批注、能否决，条目按「标题＋做法＋验收」记录。

## 它是什么

一块挂在 DSH 左侧的计划看板。任务写在当前工作区的 `.dsh/plan-board.md` 里，文件就是唯一真相：
模型用普通文件工具或 `/aboard` 命令改它，界面只负责把它渲染得好用。

## 界面在哪

- **左侧导航**：一个「计划板」图标，点开是整页看板。
- **会话视图**：会话头部的视图行多一个「计划板」标签页，内容与整页一致。
- **聊天**：手打 `/aboard` 渲染成一张卡片（总进度条、每个阶段的 done/total 与细进度、目标摘要，右上角「打开看板」可直接跳转）；面板通过命令读写时产生的记录会在聊天里折叠、不显示。

## 文件格式

```md
# 计划板 · 项目名

> 目标：一句话说明这一轮要达到什么。

## P1 · 分组名

- [ ] 一句完整人话的任务标题  @P0 @选 @start=2026-11-15T16:53
  做法：具体怎么做。
  验收：怎么算做完，尽量写可验证的标准。
  批注：用户的意见，会写回文件。
```

状态：`[ ]` 未开始、`[~]` 进行中、`[x]` 完成、`[-]` 已否决（灰掉保留）。
标记：`@P0`–`@P3` 优先级、`@选` 已挑选、`@弃` 已否决、`@start=` 开始时间、`@序=N` 拖拽后的顺序。

## 让模型开工（批量）

先把要做的条目选进「接下来」（点条目左边的圈，或设 P0–P3，拖拽可排序），然后在这一列顶部：

选进「接下来」有两种方式：点条目左边的状态圈，或者**直接把任务从「整体」拖进「接下来」**；
在「接下来」里拖动可以排序，拖回「整体」就是移出。然后在这一列顶部：

- **串行**：第一条标成进行中，整批按顺序交代给模型，一条做完再下一条；
- **并行**：整批都标成进行中，让模型为每条各派一个子代理同时跑，最后汇总。

一次点「让他做这批 · N」只投递一条**一句话**的用户消息：

```
【计划板】串行做第 4、5、6 条。执行约定：加载 skill `plan-board`。
```

详细规则放在工作区的 `plan-board` 技能里（`.dsh/skills/plan-board/SKILL.md`）：
开工前用 `plan_board_status` 标进行中、做完标完成、卡住时留批注、结束后只做简短汇总。
唤醒失败会回滚看板状态，并在面板顶部显示原因。

## 面板能做什么

- 「正在做」条：显示所有进行中的任务（标题、验/做法、秒级计时），下面接着显示**排队中的整批任务**（#1 #2 …，最多 6 行）；
- 真实运行状态：读取当前会话的 running，与「有没有标进行中」交叉提示；
- 每条可批注（写回文件）、可标为「不要」（灰掉保留，可恢复）；
- 详细度检查：缺验收或标题过短的条目挂「简略」标；
- 分组折叠、已完成折叠、搜索、键盘操作（↑↓ / 空格 / 0–3 / Enter）；
- 「接下来」列固定在视野内（滚动时不跟着跑），可从左侧拖入、内部拖动排序、拖回左侧取消；
- 完成的条目**自动离开**「接下来」，不用手动拖走；
- 右上角的垃圾桶按钮可以一次清空队列里的全部选择和优先级（带二次确认，任务本身不会被删除）；
- 「接下来」里也能直接点徽章改 P0–P3。

## 模型侧工具

- `plan_board_write`：把一批任务写进指定分组。每条必须给出标题、做法、验收；
  标题少于 20 字或缺做法/验收会被拒绝，并返回逐条补齐提示；
- `plan_board_status`：把某条在 `todo` / `doing` / `done` / `dropped` 之间切换，
  进行中记录 `@start`，完成时清除。

## 命令

`/aboard` 裸调用显示分组摘要；子命令：`list` `json` `next` `batch` `clear` `start` `pick` `prio` `doing` `done` `undone` `drop` `undrop` `note` `reorder` `goal`。

## 已知限制

- 没有模型侧工具，任务由模型直接改文件生成（P3 计划中）；
- 面板 3 秒轮询文件，不是文件系统监听；
- 「当前在跑哪个工具」尚未接入，只显示会话运行/空闲；
- 语言目前只有中文文案，locale 字典待补。
