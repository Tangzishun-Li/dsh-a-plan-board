## 0. 一句话

一个挂在 DSH 左侧的「计划看板」：我把阶段任务用**人话**写进看板；你在看板右列挑要做哪条（打勾或给优先级）；我做完了就在那条前面打勾并划线。

## 1. 使用流程（分镜）

| # | 谁 | 动作 | 屏幕上发生什么 | 数据变化 |
|---|---|---|---|---|
| S0 | 你 | 对话里说「拆一下任务」，或输入 `/aboard` | 输入框出现命令菜单，选中回车 | — |
| S1 | 我 | 调用写板工具，分 P1/P2/P3 写 3–6 条任务 | 看板出现条目；每条是一句完整人话（短于 12 字直接被我拒绝重写） | 写入 `.dsh/plan-board.md` |
| S2 | 你 | 看对话 | 聊天流里出现「计划板」卡片：`P1 · 3 条`、进度 `2/5`、每条一行 | 读同一份数据 |
| S3 | 你 | 点左侧导航的「计划板」图标 | 左侧展开一整页：**左列=全部任务**（按 P 分组，完成项带勾和删除线），**右列=我的选择**（打勾模式 / 优先级模式，可切换） | — |
| S4 | 你 | 在右列勾一条，或给它 P1 | 该行立刻进入「我的选择」，计数与顺序更新 | 写回文件（行尾标记） |
| S5 | 我 | 开始做 → 完成 | 那条变成「进行中」高亮；完成后 ✓ + 删除线 + 组进度 +1 | 写回文件 |
| S6 | 你/我 | 全部完成 | 看板切到完成态（克制，不弹窗） | — |

**关键约束（你强调的）**：任务文案必须是完整人话，不许缩写成「打通 API」这种标签。→ 工具 schema 校验长度 + 提示词明说，双保险。

## 2. 界面 × 状态矩阵（「很多样式」就是这里）

| 状态 | 左列（我的任务） | 右列（你的选择） | 聊天卡片 |
|---|---|---|---|
| 空态 | 「还没有计划」+ 引导文案（让我拆 / 输入 /board） | 灰显 | 不出现 |
| 生成中 | 3 个骨架行 + 顶部进度条 | 灰显 | 「正在拆任务…」 |

| 已选（打勾式） | 选中行左侧出现细边 | ✓ 列亮起 | 「已选 2 条」 |
| 已选（优先级式） | 行尾徽章 P1/P2/P3 | 按 P 重排 | 「P1 有 2 条」 |
| 进行中 | 当前项脉冲点 + 左侧高亮 | 该行锁定 | 「正在做：…」 |
| 部分完成 | `✓` + 删除线 + 降透明度 | 已完成行划掉 | 进度 `2/5` |
| 全完成 | 全部划线 + 空态文案 | — | 「全部完成」 |
| 长列表 | 分组可折叠、组内滚动 | 跟随滚动 | 只显示前 3 组 |
| 窄宽度 | 两列塌成一列（选择列变成行内开关） | — | 收成单行 |
| 亮/暗 | 主题 token 自动切换 | 同 | 同 |
| 中/英 | locale 字典 | 同 | 同 |
| 异常 | 写入失败 toast；文件被外部改动 → 「已重新载入」 | — | 失败原因 |
| 键盘 | ↑↓ 移动、空格勾选、1/2/3 设优先级、Enter 开始 | — | — |

样式工作量集中在：优先级徽章、勾选控件、删除线动效、分组头、进度条、进行中脉冲、空态插图。

## 3. 数据模型（三个方案，推荐 A）

### A. 文件即真相（推荐）

工作区里 `.dsh/plan-board.md`，插件读它、写它、渲染它。

```md
# 计划板

## P1 · 打通管道
- [ ] 在工作区里建好插件骨架，写三个文件，装好后能在会话头部看到新的标签页  @P1
- [x] 让左侧导航多出一个图标，点开是一整页，先只放标题和一句说明
- [~] 探明客户端到主机的数据通道：面板上点一下，主机能收到并写回
```

约定：

- `[ ]` 未完成 / `[x]` 完成 / `[~]` 进行中
- 行尾 `@P1 @P2 @P3` = 你设的优先级；行尾 `@选` = 你打的勾
- `## P1 · 标题` 这样的二级标题 = 阶段分组；组内条目数即 `几条`

为什么推荐：和你「像 md 一样划掉」的心智完全一致；我能直接用现有 edit 工具改；你能直接开文件改；git 能 diff；插件卸载数据还在。
代价：格式约定要稳，我手抖改坏格式的风险 → 工具写入 + 解析容错双重兜底。

### B. JSON 状态 + 工具写入

`.dsh/plan-board.json`，id 稳定、字段自由；但人不可读、不能 git diff、必须通过工具改。备选。

### C. 插件内部存储（`ctx.storageDomain`）

不碰工作区，干净；但换项目不共享、看不到、外部不可编辑。不推荐做主方案。

## 4. 技术方案

```
[对话/模型] --工具--> [Host 插件] --读写--> .dsh/plan-board.md
                          ^
[看板面板/聊天卡片] --命令 RPC-->  |
```

- **Host 半区**：注册工具（写板 / 勾选 / 置进行中）、注册 `/aboard` 命令、读写与解析文件、校验人话长度
- **Client 半区**：`sidebar.panellist` 图标 + `main` 主面板（整页看板）、`conversation.chat.commandview` 聊天卡片
- **通道（已探明）**：
  - 读取：客户端 `ctx.remote.workspaceFiles.read(sessionId, path, {})`（只读、按会话授权），可直接读 `.dsh/plan-board.md`
  - 写回：`ctx.remote.commands.execute(sessionId, '/aboard ...', [])` 调 Host 命令，命令里读写文件
  - 聊天卡片：`conversation.chat.commandview` 按命令名接管渲染（RPC 调用可用它渲染成不可见，避免刷屏）
  - 命令处理器里可用 `invocation.agent.followup(...)` 触发模型回合（`/aboard` 让我拆任务依赖它）
- **刷新**：面板可见时轮询 / `workspaceFiles.changes()` 变更流（P2 定）

已核实（读安装版源码/实时 Slot 树/M1 实测）：

- `sidebar.panellist`（左侧导航图标）+ `main`（keyed 主面板，`conversation` 已占一 key）— **M1 实测通过**
- `conversation.view`（会话视图 tab）— **M1 实测通过**
- `ctx.commands.register()`（Host 斜杠命令，`invocation.agent` / `rawInput`）
- `ctx.remote.workspaceFiles.read(sessionId, path, {})`（客户端只读读文件）
- `ctx.remote.commands.execute(sessionId, line, [])`（客户端调 Host 命令，返回 `{ok, value:{result}}`）
- `conversation.chat.commandview`（按命令名渲染聊天卡片，已有 `team` 先例）

仍待撞：

- U2 命令处理器里能否触发模型回合（`agent.followup`）——"`/aboard` 让我列任务"依赖它
- U4 写回后客户端如何感知（轮询 vs `workspaceFiles.changes` 变更流）

## 5.5 开发循环（重要）

Host 端在发布时**快照** `client.js` / `index.js`；本机 `/plugins/events` 热更新流又是坏的（404）。
→ 改完代码**必须重启 DSH**（或由插件管理器关/开本插件）才会生效，刷新页面不够。
→ 所以每一轮改完要「攒一批」再重启，不要一行一重启。

## 6. 风险

- **R1** 第三方插件注册不了 `main` 面板 → 退到 Plugins 详情页（P1.4）
- **R2** Client→Host 没有公开 RPC → 退到"只读看板 + 模型通过工具改"（交互降级）
- **R3** 命令触发模型回合不被允许 → `/aboard` 只查看，生成靠对话里直接说
- **R4** 我和用户同时改文件 → 冲突策略：以文件为准，面板改动前重读，目标行消失就提示
- **R5** 纯 JS 写 React，无构建工具 → 单文件起步，样式内联
