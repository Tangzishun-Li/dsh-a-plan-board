# 计划板执行约定

当用户通过计划板派活时，按这里的规定执行，不要另起一套流程。

## 先读板子

1. 读 `.dsh/plan-board.md`，确认要做的条目序号、标题、做法、验收和批注。
2. 序号就是看板上条目的显示编号（从上往下数第 n 条 `- [ ... ]` 行）。

## 状态流转（必须用工具，不要手改文件）

- **开工前**：`plan_board_status { index, state: "doing" }` —— 它会写开始时间，面板据此显示计时。
- **做完**：`plan_board_status { index, state: "done" }` —— 它会去掉开始时间。随后该条自动离开「接下来」队列。
- **做不到 / 要换方案**：保持 `doing`，在该条目下用 edit 追加一行 `  批注：<卡在哪、需要用户定什么>`，然后在对话里说明，不要擅自标完成。
- **被用户否掉**：不要自己 drop，等用户操作。

## 执行要求

- 条目里的「做法」「验收」是硬要求：验收标准没达到就不算完成。
- 一次只推进一条（除非派活消息明确说是并行/串行批量）。
- 并行时：为每条各派一个子代理，各自独立完成；你在主会话里汇总。
- 不改动条目的标题、做法、验收原文；只改状态和追加批注。
- 不删除任何条目，不清理别人的 `@选` / `@序` 标记。

## 汇报

全部结束后用一小段汇总：每条一行（序号 + 结果 + 关键改动 / 遗留问题），不要复述做法细节，不要贴大段代码。
